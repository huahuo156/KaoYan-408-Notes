###### 程序查询方式

CPU <mark style="background:#40a9ff">不断轮询/定时查询</mark>检查 I/O 控制器中的“状态寄存器”，检测到状态为“已完成”之后，再从数据寄存器取出输入数据

![[pic/输入输出系统--程序查询方式.png#pic-center|程序查询方式|1158]]
![[pic/输入输出系统-程序查询方式流程图.png#pic-center|流程图|1069]]
处理过程：
① CPU 执行初始化程序，预置传送参数（如起始地址、数据量等）。
② 向 I/O 接口发送命令字，启动外设。
③ 循环读取外设状态寄存器。
④ 若设备未就绪，则继续查询；若就绪，则执行一次数据传送。
⑤ 修改地址和计数器参数。
⑥ 判断传送是否完成，若未完成则返回步骤③，直至计数器归零。

优点：接口设计简单、设备量较少
缺点：CPU 在信息传输过程中要<mark style="background:#40a9ff">花费大量时间用于查询和等待</mark>，而且在一段时间内只能和一台外设交换信息，效率低下；外设、传输事务与 CPU 是<mark style="background:#40a9ff">串行</mark>的

>[!important] 最小 CPU 定时查询时间间隔的计算


###### 程序中断方式
等待键盘等<mark style="background:#40a9ff">慢速 I/O 设备</mark>时 CPU 可以先去执行其他程序，键盘等慢速 I/O 设备完成后通过 I/O 控制器向 CPU 发出中断请求，CPU 响应中断请求，并取走输入数据
![[pic/输入输出系统--程序中断方式.png#pic-center|程序中断方式|1050]]

###### DMA 控制方式(Direct Memory Access，直接内存访问)
主存与<mark style="background:#40a9ff">高速 I/O 设备(如网卡、声卡、显卡、磁盘)</mark>之间有一条<mark style="background:#40a9ff">直接数据通路（DMA总线）</mark>。CPU 向 DMA 接口发出“读/写”命令，并指明<mark style="background:#40a9ff">主存地址、磁盘地址、读写数据量</mark>等参数。
DMA 控制器自动控制磁盘与主存的数据读写，每完成一整块数据读写（如 1 KB 为一整块），才向 CPU 发出一次中断请求
>[!caution] 
>1. DMA 控制器属于 I/O 控制器/接口
>2. 磁盘驱动器指的即为 磁盘本身，不属于 I/O 接口

![[pic/输入输出系统--DMA控制方式.png#pic-center|DMA 控制方式|987]]

#### 字符显示器的显示原理
![[pic/输入输出系统--字符显示器.png#pic-center|字符显示器显示原理|735]]
<mark style="background:#40a9ff">字符显示器属于 阴极射线管显示器(CRT)</mark>
显示字符的方法<mark style="background:#40a9ff">以点阵为基础</mark>。点阵是指由 $m\times n$ 个点组成的阵列。点阵的多少取决于显示字符的质量和字符窗口的大小。字符窗口是指每个字符在屏幕上所占的点数，它包括字符显示点阵和字符间隔。

将<mark style="background:#40a9ff">点阵存入由 $\mathrm{ROM}$ 构成的字符发生器</mark>中，在 $\mathrm{CRT}$ 进行光栅扫描的过程中，从字符发生器中依次读出某个字符的点阵，按照点阵中 $0$ 和 $1$ 代码不同控制扫描电子束的开或关，从而在屏幕上显示出字符。对应于每个字符窗口，所需显示字符的 $\mathrm{ASCII}$ 代码被存放在视频存储器 $\mathrm{VRAM}$ 中，以备刷新。

## I/O 接口
### I/O 接口的作用
- **数据缓冲**：通过**数据缓冲寄存器**（DBR）达到主机和外设工作速度的匹配
- **错误或状态监测**：通过**状态寄存器**反馈设备的各种错误、状态信息，供CPU查用
- **控制和定时**：接收从控制总线发来的控制信号、时钟信号
- **数据格式转换**：串-并、并-串等格式转换
- **与主机和设备通信**：实现主机—— I/O 接口—— I/O 设备之间的通信

### I/O 接口的工作原理
![[pic/输入输出系统--IO接口的工作方式.png#pic-center|I/O 接口的工作原理|759]]
①发命令：发送命令字到 I/O 控制寄存器，向设备发送命令（需要驱动程序的协助）
②读状态：从状态寄存器读取状态字，获得设备或 I/O 控制器的状态信息
③读/写数据：从数据缓冲寄存器发送或读取数据，完成主机与外设的数据交换

>[!important] 数据线、控制线、地址线上传输的数据(同图上所示)
>1. 数据线：读写数据、状态字、控制字、中断类型号
>2. 地址线：要访问的 I/O 端口地址
>3. 控制线：读/写控制信号、中断请求与响应信号、总线仲裁信号、设备握手信号

注意：
1. <mark style="background:#40a9ff">控制寄存器、状态寄存器在使用时间上是<mark style="background:#fff88f">分时</mark>的</mark>，因此有的 I/O 接口可将二者合二为一
2. I/O 控制器中的各种<mark style="background:#40a9ff">寄存器</mark>称为 <mark style="background:#40a9ff">I/O 端口</mark>
3. “在主机侧仅能数据并行传输”，是过时的说法

>[!addition] 与操作系统相关的内容
>1. I/O 接口存在 一对多 的情况，所以 I/O 接口中的各类端口/寄存器可能存在多个，且该些端口/寄存器都具有相应的地址，便于 CPU 的操作
>2. I/O 接口的组成(在操作系统中对 I/O 接口进行了进一步的简化)：
>	1. CPU 与控制器之间的端口/寄存器(实现控制器与 CPU 之间的通信)
>	2. I/O 逻辑(负责识别 CPU 发出的命令，并向设备付出命令)
>	3. 控制器与设备之间的接口(实现控制器与设备之间的通信)

### 接口与端口
在 I/O 设备的背景下，端口即为接口电路中可被 CPU 直接访问的 I/O 控制器中的各种<mark style="background:#40a9ff">寄存器</mark>，主要包括 <mark style="background:#fff88f">数据端口(读 & 写)、控制端口(写)、状态端口(读)</mark>

#### 统一编址/内存映像 I/O
特点：
- <mark style="background:#fff88f">把 $\text{I/O}$ 端口当做存储器的单元进行地址分配</mark>，用统一的访存指令就可以访问 $\text{I/O}$ 端口，又称存储器映射方式。
- <mark style="background:#fff88f">靠不同的地址码区分</mark>内存和 $\text{I/O}$ 设备，$\text{I/O}$ 地址<mark style="background:#fff88f">要求相对固定在地址的某部分</mark>。

优点：
- 不需要专门的输入/输出指令，<mark style="background:#40a9ff">所有访存指令都可直接访问端口</mark>，程序设计灵活性高
- 端口有较大的编址空间
- <mark style="background:#40a9ff">读写控制逻辑电路简单</mark>

缺点：
- 端口<mark style="background:#40a9ff">占用了主存地址空间</mark>，使主存地址空间变小
- 外设寻址时间长（地址位数多，<mark style="background:#40a9ff">地址译码速度慢</mark>）


#### 独立编制
特点：
- <mark style="background:#fff88f">$\text{I/O}$ 端口地址与存储器地址无关</mark>，独立编址 $\text{CPU}$ <mark style="background:#fff88f">需要设置专门的输入/输出指令</mark>访问端口，又称 $\text{I/O}$ 映射方式。
- <mark style="background:#fff88f">靠不同的指令区分</mark>内存和 $\text{I/O}$ 设备。

优点：
- 使用专用 $\text{I/O}$ 指令，程序编制清晰
- $\text{I/O}$ 端口地址位数少，<mark style="background:#40a9ff">地址译码速度快</mark>
- $\text{I/O}$ 端口的地址<mark style="background:#40a9ff">不占用主存地址空间</mark>

缺点：
- <mark style="background:#40a9ff">$\text{I/O}$ 指令类型少</mark>，一般只能对端口进行传送操作，程序设计灵活性差
- 需要 $\text{CPU}$ 提供存储器读/写、$\text{I/O}$ 设备读/写两组控制信号，<mark style="background:#40a9ff">增加了控制逻辑电路的复杂性</mark>
>[!important] I/O 指令与 CPU 指令
><mark style="background:#40a9ff">I/O 指令是指令系统的一部分，是机器指令的一部分</mark>，但其为了反映与 I/O 设备交互的特点，<mark style="background:#40a9ff">格式与其他通用指令相比有所不同</mark>

### 程序中断方式
#### 基本概念
**程序中断**：是指在计算机执行现行程序的过程中，出现某些急需处理的异常情况或特殊请求，CPU 暂时中止现行程序，而转去对这些异常情况或特殊请求进行处理，在处理完毕后 CPU 又自动返回到现行程序的断点处，继续执行原程序。

**外中断**：由 <mark style="background:#40a9ff">CPU 外部的硬件设备</mark>(如键盘、网卡、硬盘、定时器等) 发出的信号，打断 CPU 当前正在执行的程序，迫使 CPU 暂停当前任务，转而去处理这个突发事件，处理完毕后再返回原程序继续执行；<mark style="background:#fff88f">属于异步事件，具有随机性</mark>。

**内中断**：又称“异常”，由 <mark style="background:#40a9ff">CPU 内部事件触发</mark>、<mark style="background:#40a9ff">与当前执行指令直接相关</mark>的中断信号；<mark style="background:#fff88f">属于同步事件，具有确定性、可重现性</mark>。
>[!important] 中断与异常
>1. 处理流程：
>	1. 中断处理流程(见下文[[#^10da6b|处理流程]])
>	2. 异常处理流程
>		- 若 CPU 执行当前指令触发<mark style="background:#fff88f">“异常”，CPU 通常会在其执行过程中或完成时立即响应</mark>；响应结束后，CPU 暂停当前的程序，<mark style="background:#fff88f">保存现场</mark>，并转移至相应的服务程序；处理完成后，若事件可恢复，系统将通过执行异常放回指令，恢复上下文并继续原程序：<mark style="background:#fff88f">异常通常需要重新执行当前指令</mark>(触发异常的指令)。
>2. 分类：
>	1. 中断分类
>		1. 可屏蔽中断
>		2. 不可屏蔽中断
>	2. 异常分类
>		1. **故障**：指令启动后、执行前被检测的异常事件
>			例子：<mark style="background:#fff88f">访存缺页、段错误</mark>
>		2. **自陷**/陷阱/陷入：一种预先安排的、用于主动转入操作系统内核的同步事件；与故障不同的是，陷阱是在正常执行完毕后才被触发的；属于程序性异常，并且处理完后，CPU 总是<mark style="background:#40a9ff">从自陷指令的下一条指令继续执行</mark>
>			例子：系统调用、<mark style="background:#fff88f">断点调试</mark>
>		3. **终止**：在指令执行过程中发生<mark style="background:#40a9ff">严重的硬件故障</mark>，导致系统无法继续正常运行，程序被迫终止，即程序无法返回，不能继续执行
>			例子：<mark style="background:#fff88f">除数为 0</mark>、非法指令
>		4. 其他经典例子：溢出、栈溢出、地址越界等
>3. 检查时机：
>	1. 中断：<mark style="background:#fff88f">每个指令周期末尾</mark>，CPU 都会检查是否会有外中断信号需要处理
>	2. 异常：CPU <mark style="background:#fff88f">在执行指令时</mark>会检查是否有异常发生

#### 工作流程

^10da6b

1. **中断请求**
	中断源向 CPU 发送中断请求信号。
2. **中断响应**
	响应中断的条件；
	*中断判优*：多个中断源同时提出请求时通过中断判优逻辑响应一个中断源
3. **中断处理**
	*中断隐指令*
	*中断服务程序*

#### 中断请求标记
(判断是哪个设备发来的中断信号)

要点：
1. CPU 无法立即响应中断请求，需在当前指令周期的末尾统一响应
2. 每个中断源向 CPU 发出中断请求的时间是随机的。
3. 为了记录中断事件并区分不同的中断源，中断系统需对每个中断源设置*中断请求标记触发器* INTR，当其状态为 “1” 时，表示中断源有请求。
4. 这些触发器可组成中断请求标记寄存器，该寄存器可集中在 CPU 中，也可分散在各个中断源中。

#### 中断响应
##### 中断响应条件
对于外中断，CPU 是在统一的时刻即每条指令执行阶段结束前向接口发出中断查询信号，以获取 I/O 的中断请求，也就是说，CPU 响应中断的时间是在每条指令执行阶段的结束时刻。

CPU 响应中断必须满足以下 3 个条件：
① 中断源有*中断请求*。
② CPU 允许中断即*开中断*。
③ *一条指令执行完毕，且没有更紧迫的任务*。

##### 中断判优
###### 实现
中断判优既可以用硬件实现，也可用软件实现：
1. **硬件实现**是通过*硬件排队器*实现的，它既可以设置在 CPU 中，也可以分散在各个中断源中(具体硬件实现不被要求)；
2. **软件实现**是通过*查询程序*实现的。

###### 优先级设置
1. 硬件故障中断属于最高级，其次是软件中断；
2. 非屏蔽中断优于可屏蔽中断；
3. DMA 请求优于 I/O 设备传送的中断请求
4. 高速设备优于低速设备；
5. 输入设备优于输出设备；
6. 实时设备优于普通设备。

#### 中断处理
##### 中断隐指令
>中断隐指令并<mark style="background:#ff4d4f">不属于</mark> 系统指令，并且整个阶段由 <mark style="background:#ff4d4f">硬件(或者说 **CPU**)</mark> 自动完成，不涉及操作系统

主要任务：
① **关中断**。在中断服务程序中，为了保护中断现场（即 CPU 主要寄存器中的内容）期间<mark style="background:#40a9ff">不被新的中断所打断，必须关中断</mark>，从而保证被中断的程序在中断服务程序执行完毕之后能接着正确地执行下去。
>中断隐指令/<mark style="background:#ff4d4f">硬件</mark> 将 “允许中断触发器” 由 1 置为 0，实现“关中断”

② **保存断点**。为了保证在中断服务程序执行完毕后能正确地返回到原来的程序，必须<mark style="background:#40a9ff">将原来程序的断点(即程序计数器(<mark style="background:#ff4d4f">PC</mark>)和状态寄存器(<mark style="background:#ff4d4f">PSW</mark>))的内容）保存起来</mark>；可以存入堆栈，也可以存入指定单元。断点的保存是通过<mark style="background:#ff4d4f">硬件</mark>完成的。

③ **引出中断服务程序**。引出中断服务程序的实质就是取出中断服务程序的入口地址并传送给程序计数器（PC）。
>[!important] 引出中断服务程序的方式
>1. 软件查询法
>2. **硬件向量法**(重点)
>	1. 由**硬件产生**向量地址，再根据向量地址找到入口地址
>	2. 向量地址由“中断向量地址形成部件”根据中断判优中的排队器的输出产生
>	3. 数据流：根据中断类型号计算得到向量地址，并根据向量地址取出主存中存储的中断向量；中断向量可直接指向入口地址，或者指向无条件跳转指令，执行后将 PC 中的值更改为 入口地址

>[!attention] “操作系统”部分：CPU 由用户态向内核态的转变，也是在该阶段完成，并且由硬件自动完成
##### 中断服务程序
>此处的操作由 <mark style="background:#40a9ff">操作系统</mark> 主导，较少涉及硬件部分

主要任务：
① **保护现场**
	保存<mark style="background:#40a9ff">通用寄存器</mark>中的数据
② **中断服务**(设备服务)
	主体部分，执行 I/O 指令，如通过程序控制需打印的字符代码送入打印机的缓冲存储器中
③ **恢复现场**
	通过出栈指令或取数指令<mark style="background:#40a9ff">把之前保存的信息送回寄存器中</mark>
④ **中断返回**
	通过中断返回指令回到原程序断点处。

##### 中断屏蔽技术
屏蔽字的作用：改变的是<mark style="background:#40a9ff">处理优先级</mark>
>[!importnat] 中断屏蔽字 与 中断判优
>中断优先级包括 **响应优先级** 和 **处理优先级**，中断屏蔽字改变的是处理优先级，而中断响应优先级是由中断查询程序或中断判优电路决定的，反映的是多个中断源同时哪个先被响应，即**中断服务程序开始执行的顺序**

中断屏蔽技术**主要用于多重中断**，CPU 要具备多重中断的功能，须满足下列条件：
① 在中断服务程序中提前设置*开中断指令*。
② 优先级别高的中断源有权中断优先级别低的中断源。

每个中断源都有一个屏蔽触发器，1 表示屏蔽该中断源的请求，0 表示可以正常申请，所有屏蔽触发器组合在一起，便构成一个屏蔽字寄存器，屏蔽字寄存器的内容称为屏蔽字。

> 1. 在单重中断中，若 CPU 处于开中断状态，检测到中断请求，则当前处于中断周期并且存在中断请求，所以应立即响应
> 2. 在多重中断中，若 CPU 正在处理某中断服务时，检测到其他中断请求，则说明有其他未被屏蔽或优先级更高的中断请求，需优先处理该中断请求

###### 设置屏蔽字
1. <mark style="background:#40a9ff">一般用 1 表示屏蔽，0 表示正常申请</mark>。
2. <mark style="background:#40a9ff">每个中断源对应一个屏蔽字</mark>（在处理该中断源的中断服务程序时，屏蔽寄存器中的内容为该中断源对应的屏蔽字）。
3. <mark style="background:#40a9ff">屏蔽字中 1 越多，优先级越高</mark>；每个屏蔽字中至少有一个 1 (至少要能屏蔽自身的中断)。

### DAM 控制方式
#### 传输过程
预处理：
CPU 向 DMA 控制器指明：
1. 要<mark style="background:#40a9ff">输入还是输出</mark>；(数据流方向)
2. 要<mark style="background:#40a9ff">传送多少个数据</mark>；(数据量)
3. <mark style="background:#40a9ff">数据在主存、外设中的地址</mark>；(数据位置)
4. 设备的选择 (目的地)

传送前：
接受外设发出的 <mark style="background:#40a9ff">DMA 请求(仅指总线请求)</mark>（外设每传送一个字的请求），并向 CPU 发出总线请求。
CPU 响应此总线请求，发出总线响应信号，接管总线控制权，进入 DMA 操作周期。

传送时：
确定传送数据的主存单元地址及长度，并能<mark style="background:#fff88f">自动修改主存地址计数和传送长度计数</mark>。
规定数据在主存和外设间的传送方向，发出读写等控制信号，执行数据传送操作

传送结束：
向 CPU 报告 DMA 操作的结束，进入<mark style="background:#fff88f">后处理</mark>阶段，CPU 的任务为 <mark style="background:#fff88f">校验数据的正确性</mark> 等

#### DMA 控制器
(单总线)
![[pic/输入输出系统--DMA控制器内部.png#pic-center|DMA控制器组件|1206]]
注：采用系统单总线时，在 DMA 传送过程中，DMA 控制器将接管 CPU 的地址总线、数据总线和控制总线，CPU 的主存控制信号被禁止使用。而当 DMA 传送结束后，将恢复 CPU 的一切权利并开始执行其操作。

#### DMA 传送方式
当采用系统三总线时，存在 CPU 与 DMA 控制器访问主存冲突的问题
主存和 DMA 控制器之间有一条数据通路，因此主存和 I/O 设备之间交换信息时，不通过 CPU。但当I/O 设备和 CPU 同时访问主存时，可能发生冲突。

> DMA 控制器使用总线的优先级比 CPU 高

![[pic/输入输出系统--DMA传送方式.png#pic-center|DMA 传送方式|1337]]
>[!note] 
>DMA 与 CPU 交替访存适用于*工作周期*(而非总线周期)大于存取周期的情况

#### DMA 控制方式与程序中断方式的对比
|               | 程序中断方式                                                                                                                                | DMA                                                                                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据传送          | 程序控制<br>程序的切换 -> 保存和恢复现场                                                                                                              | 硬件控制<br>CPU 只需进行预处理和后处理                                                                                                                                                            |
| 第一次请求         | I/O 设备-> CPU:<mark style="background:#fff88f">中断请求</mark>，数据准备完毕，请求 CPU 处理时间<br>响应阶段：<mark style="background:#40a9ff">指令执行周期结束</mark> | DMA 控制器-> CPU:申请总线使用，进行 I/O 设备和主存之间的数据传输，即<mark style="background:#d3f8b6">“DMA 请求”</mark>，由外设发出<br>响应阶段：<mark style="background:#40a9ff">总线事务结束/总线空闲/当前指令流阶段结束时</mark>(可在指令执行中响应) |
| 第二次请求         | CPU -> I/O 设备:执行 I/O 指令，传输数据<br>阶段：执行中断服务程序时                                                                                          | DMA 控制器-> CPU:<mark style="background:#fff88f">中断请求</mark>，CPU 进行后处理<br>响应阶段：指令执行周期结束                                                                                              |
| 数据流           | I/O 设备 -> CPU -> 主存                                                                                                                   | I/O 设备 -> DMA 控制器 -> 主存                                                                                                                                                            |
| 控制方           | <mark style="background:#40a9ff">软件</mark>控制数据传输                                                                                      | <mark style="background:#40a9ff">硬件</mark>控制数据传输                                                                                                                                   |
| 场景            | CPU 控制，<mark style="background:#40a9ff">低速设备</mark>                                                                                   | DMA 控制器控制，<mark style="background:#40a9ff">高速设备</mark>                                                                                                                             |
| 优先级           | 优先级低于 DMA                                                                                                                             | 优先级高于中断                                                                                                                                                                            |
| 异常处理          | 能处理异常事件                                                                                                                               | 仅传送数据                                                                                                                                                                              |
| 外设与 CPU 串并行情况 | 外设与 CPU 并行，传输事务与 CPU 串行                                                                                                               | 外设、传输事务 与 CPU 并行                                                                                                                                                                   |

>[!addition] 与操作系统相关的内容
>1. 进程状态的转换：程序直接控制方式 不涉及进程状态的转换，而 程序中断方式、DMA 控制方式 涉及进程状态的转换：从运行态转为阻塞态等待
>2. 内核态与用户态：DMA 控制方式、程序中断控制方式 在完成 I/O 操作后会向 CPU 发送中断请求，使 CPU 介入，使得 从用户态转为内核态；进一步，DMA 控制方式预处理为 I/O 请求，使得系统从用户态转为内核态，并在内核态执行相应的设备驱动程序设置传输参数，并将自身阻塞；后处理为 中断服务程序。

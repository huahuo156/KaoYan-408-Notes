## ~~网络层的功能~~
### 异构网络互联
- “异构”：每个网络的拓扑结构不同、物理层&链路层的实现不同、主机类型也各不相同
- 重要的设备：<mark style="background:#fff88f">路由器</mark>($Router$)，也称为网关($Gateway$)，<mark style="background:#fff88f">实现不同协议的网络的互连</mark>

### 路由与转发
####  路由
- <mark style="background:#fff88f">各个路由器之间相互配合</mark>，规划$IP$数据报（分组）的最佳转发路径
- 注：各个路由器需要运行“路由协议”，最终生成各自的“路由表”

#### 转发
- <mark style="background:#fff88f">一台路由器</mark>，根据自己的“转发表”，将收到的$IP$数据报从合适的接口转发出去
- 注：转发表 = 精简版路由表。更精简的数据结构有助于快速检索

### 拥塞控制
#### 拥塞
- 原因：网络上出现过量分组，超负荷，引起网络性能下降
- 现象：网络上的分组数增加，但吞吐量反而降低

#### 拥塞控制方法
##### ~~开环控制（静态的方法）~~
- 在部署网络时，就提前设计好预防拥塞的方法。<mark style="background:#fff88f">一旦网络系统开始运行，就不再修改</mark>

##### ~~闭环控制（动态的方法）~~
- <mark style="background:#fff88f">动态监视</mark>网络状态，<mark style="background:#fff88f">及时发现</mark>哪里发生拥塞，并将拥塞信息<mark style="background:#fff88f">传递</mark>给相关路由器（如：通过$ICMP$）
- 相关路由器及时调整“路由表”

## IPv4
IPv4 协议的地位：互联网的核心协议
![[pic/各网络协议之间的关系.png#pic-center|各网络协议之间的关系|743]]
### IP 分组格式
![[pic/IP 分组的格式.png#pic-center|IP 分组的格式|737]]
1. **版本(4 bit)**：指明 IP 协议版本采用的是 v4 或 v6
2. **首部长度(4 bit)**：指明 IP 协议首部的长度，且<mark style="background:#fff88f">以 4B 为单位</mark>
	1. 可变部分，长度 0~40 B；<mark style="background:#fff88f">首部的固定部分为 20 B</mark>
	2. 填充，将首部填充为 4B 的整数倍 
3. 区分服务(1 B)
4. **总长度(16 bit)**：指明整个 IP 分组的长度，<mark style="background:#fff88f">单位为 1B</mark>，故**理论**上 IP 分组支持的数据部分最大长度为 $2^{15}-1-20=65515$ B
5. **标识(16 bit)**：源主机用递增计数器，<mark style="background:#fff88f">为每个数据报设置标识字段，并非序号</mark>。分片时，所有分片复制原始数据报的标识字段的值，以便目的主机据此重组原数据报
6. **标志(3 bit)**：低 2 位有效
	1. MF(more fragment)：<mark style="background:#fff88f">MF=1，表示后续还有更多分片</mark>
	2. DF(don't fragment)：<mark style="background:#fff88f">DF=1，表示该分组不允许分片</mark>
7. **片偏移(13 bit)**：<mark style="background:#fff88f">表示当前分片相对于原分组的位置</mark>，<mark style="background:#fff88f">以 8B 为单位</mark>
8. **生存时间(TTL,8 bit)**：表示当前分组可以经过路由器的最大数量；<mark style="background:#fff88f">每经过一个路由器，该值减 1(先减 1 再考虑转发)</mark>，<mark style="background:#fff88f">当 TTL = 0 时，该数据报被路由器丢弃</mark>，并路由器向源主机发送 ICMP 报文报告异常
9. **协议(8 bit)**：表示该数据报携带的数据使用的何种协议，即<mark style="background:#fff88f">指明数据应交付给哪个上层协议</mark>。其中 6 表示 TCP，7 表示 UDP
10. **首部校验和(16 bit)**：值校验首部
11. **源/目的地址(32 bit)**：表示源/目的主机的 IP 地址

### IP 数据报分片
链路层数据帧能承载的最大数据量称为 最大传送单元/MTU；
由于数据链路层 MTU 的限制，过长的 IP 数据报需先进行分片后才可以传输

<mark style="background:#fff88f">分片只能发生在源主机或中间路由器上，而重组只需在目的主机上进行</mark>

除最后一个分片外，其余分片的数据长度<mark style="background:#fff88f">必须是 8B 的整数倍</mark>

### IPv4 地址

点分十进制记法：32 bit 地址，每 8 bit 一组，转换为对应的十进制数(范围为 0~255)

#### 分类的 IPv4 地址
基本格式：**<网络号:主机号>**

地址分类：
1. A 类：前 8 bit 为网络号，范围为 1~126
2. B 类：前 16 bit 为网络号，范围为 128~191
3. C 类：前 24 bit 为网络号，范围为 192~223

特殊的网络地址(不可分配给主机使用)：
1. **主机号全为 0**：表示网络本身/网络地址
2. **主机号全为 1**：表示网络的广播地址/直接广播地址
3. **127.x.x.1**：为本地回环网络，仅用于本机进程间的通信，<mark style="background:#40a9ff">既可以作为源 IP 地址，又可以作为目的 IP 地址</mark>
4. **全为 0**：表示本网络上的本主机，常用于 **DHCP**，<mark style="background:#40a9ff">仅仅可作为 源 IP 地址</mark>
5. **全为 1**：在本网络广播

#### 子网划分
基本格式：**<网络号:子网号:主机号>**

子网掩码，即 1 对应网络号，0 对应主机号 的二进制串，与 IP 地址逐位相“与”，即可得到该主机所在的子网；为兼容 分类的网络，为其使用 默认的子网掩码

路由器在交换信息时，必须同时告知目的网络地址与子网掩码；**若分组转发接口与入口一致则直接丢弃**

**默认网关**，即本子网所连路由器接口的 IP 地址，用于将数据转发至外部网络
- 在同一个子网内，**直接交付，封装层数据链路层帧**，直接发往目的主机的 MAC 地址
- 不在同一个子网内，**间接交付，将数据报发往 默认网关**，由路由器在网络层进行转发

#### 无分类编址 / CIDR
基本思想：不再做网络区分，使用“网络前缀”来识别网络部分
基本格式：**<网络前缀:主机号>/前缀长度**(不可省略)

地址划分：
1. 定长子网划分，同“划分子网”
2. 不定长子网划分：采用“<mark style="background:#ff4d4f">自顶向下的哈夫曼树构造</mark>”方法，注意<mark style="background:#ff4d4f">覆盖范围</mark>

<mark style="background:#40a9ff">最小子网：点对点链路，需至少保留 2 bit 作为子网主机号，其实仅 2 个 IP 地址可供分配(去除主机号全为 1 和全为 0 的地址)</mark>

路由聚合，即将多个较小的 CIDR 地址块合并成较大的 CIDR 地址块，但具有同一个下一跳路由；<mark style="background:#fff88f">可能会引入无效地址</mark>(但并不会影响网络性能)

网络最长匹配，即**前缀位数最多的路由**

### 网络地址转换 NAT
被保留的私有 IP 地址块，仅用于 LAN 内部，不会被路由器转发
1. 10.0.0.0/8：10.0.0.0~10.255.255.255
2. 172.16.0.0/12：172.16.0.0~172.31.255.255
3. 192.168.0.0/16：192.168.0.0~192.168.255.255

NAT 路由器根据 NAT 表实现私有 IP 向全球 IP 的映射，表项结构：**<私有 IP 地址:端口>-<全球 IP 地址:端口>**(端口为传输层的概念，实现进程间的通信)

NAT 路由器会修改接收到的 IP 数据报的<u>源 IP 地址与源端口号</u>(修改为 NAT 的全球 IP 以及 NAT 分配的端口，LAN->WAN)或<u>目的 IP 地址与目的端口号</u>(还原为私有 IP 地址与端口，WAN->LAN)，所以 NAT 路由器工作在 <mark style="background:#fff88f">**传输层**</mark>

### 地址解析协议 / ARP
在实际链路上传输数据帧时，最终必须采用 MAC 地址
**ARP 实现了 IP 地址向物理地址/MAC 地址的转换**，用于解析下一跳路由接口的 MAC 地址；<mark style="background:#40a9ff">**仅用于本局域网**</mark>，并且动态更新维护；工作在 <mark style="background:#fff88f">**网络层**</mark>，将数据封装在 <mark style="background:#fff88f">**IP 数据报**</mark>中

过程：广播寻找、单播回复
1. 封装 ARP 请求报文：<mark style="background:#fff88f">目的 MAC 地址为全 1(即广播帧)</mark>，<mark style="background:#fff88f">源 MAC 地址为请求主机的 MAC 地址</mark>
2. 被请求主机回复，向请求主机发送 ARP 响应报文：<mark style="background:#fff88f">目的 MAC 地址为请求主机的 MAC 地址(即单播帧)</mark>，<mark style="background:#fff88f">源 MAC 地址为被请求主机的 MAC 地址</mark>；被请求主机将 被请求主机的 MAC 地址与其 IP 地址映射关系进行缓存
3. 请求主机接收响应报文，缓存 被请求主机 MAC 地址与其 IP 地址的映射关系

### 动态主机配置协议 DHCP
连接到互联网上的主机的配置：
1. <mark style="background:#d3f8b6">IP 地址</mark>
2. <mark style="background:#d3f8b6">子网掩码</mark>
3. <mark style="background:#d3f8b6">默认网关</mark>
4. <mark style="background:#d3f8b6">域名服务器的 IP 地址</mark>

DHCP 工作在 <mark style="background:#fff88f">应用层</mark>，使用 <mark style="background:#fff88f">UDP(绑定在 67 号端口)</mark>，采用 <mark style="background:#fff88f">C/S 模式</mark>

过程：
1. DHCP 客户广播 “DHCP Discover” 发现报文，虽然其他设备都可以接收，但只有 DHCP 服务器才会响应
	1. 源 IP 地址：0.0.0.0，目的 IP 地址：255.255.255.255
	2. 源 MAC 地址：DHCP 客户的 MAC 地址，目的 MAC 地址：全 1
	3. IP 广播帧、MAC 广播帧：**设备刚接入网络，未被分配 IP，以及 DHCP 服务器 IP**
2. DHCP 服务器广播 “DHCP Offer” 提供报文(内容包括 子网掩码、默认网关、DNS 服务器、租用期)，注意<mark style="background:#fff88f">本网络中可能存在多个 DHCP 服务器，所以 DHCP 客户可能会收到多个 “DHCP Offer” 提供报文</mark>
	1. 源 IP 地址：DHCP 服务器的 IP 地址，目的 IP 地址：255.255.255.255
	2. 源 MAC 地址：DHCP 服务器的 MAC 地址，目的 MAC 地址：DHCP 客户的 MAC 地址
	3. IP 广播帧、MAC 单播帧：**设备仍未分配 IP，但 DHCP 服务器已知晓请求主机的 MAC 地址**
3. DHCP 客户广播 “DHCP Request” 请求报文，注意该处仍为 <mark style="background:#fff88f">广播</mark>，原因仍为 <mark style="background:#fff88f">本网络中可能存在多个 DHCP 服务器并接收到多个 “DHCP Offer” 提供报文，该主机只能选择一个，并“广而告之”</mark>
	1. 源 IP 地址：0.0.0.0(并未正式分配 IP 地址)，目的 IP 地址：255.255.255
	2. 源 MAC 地址：DHCP 客户的 MAC 地址，目的 MAC 地址：全 1
	3. IP 广播帧、MAC 广播帧：**仍未正式分配 IP，但需选择一个 Offer，并向其他 DHCP 服务器广而告之**
4. DHCP 服务器广播 “DHCP ACK” 确认报文，将 IP 地址分配给 DHCP 客户
	1. 源 IP 地址：DHCP 服务器的 IP 地址，目的 IP 地址：255.255.255.255
	2. 源 MAC 地址：DHCP 服务器的 MAC 地址，目的 MAC 地址：全 1
	3. IP 广播帧、MAC 广播帧：**仍未正式分配 IP，被选中的 Offer 对应的 DHCP 服务器向请求主机以及其他 DHCP 服务器广而告之，表示确认请求**


| 报文            | 源 IP 地址                 | 目的 IP 地址        | 源 MAC 地址                  | 目的 MAC 地址         | 备注               |
| ------------- | ----------------------- | --------------- | ------------------------- | ----------------- | ---------------- |
| DHCP Discover | 0.0.0.0                 | 255.255.255.255 | 请求主机的 MAC 地址，记为 Q-MAC     | FF-FF-FF-FF-FF-FF |                  |
| DHCP Offer    | DHCP 服务器的 IP 地址，记作 D-IP | 255.255.255.255 | DHCP 服务器的 MAC 地址，记作 D-MAC | Q-MAC             | 网络层广播帧可能链路层并非广播帧 |
| DHCP Request  | 0.0.0.0                 | 255.255.255.255 | Q-MAC                     | FF-FF-FF-FF-FF-FF |                  |
| DHCP ACK      | D-IP                    | 255.255.255.255 | D-MAC                     | Q-MAC             |                  |


### 网际控制报文协议 ICMP
ICMP 工作在<mark style="background:#fff88f">网络层</mark>，可以使得 主机或路由器 能够向源点报告网络中的差错或异常情况；封装在 <mark style="background:#fff88f">IP 数据报</mark>中传送

类型：
1. **差错报文**：
	1. **终点不可达**：路由器或主机无法交付数据报时
	2. **时间超过**：
		1. 路由器转发数据报，TTL 减为 0 时，丢弃数据报并发送差错报文
		2. 目的主机由于长时间未收齐 某数据报的全部分片时，则丢弃全部已收到的分片并发送差错报文
	3. **参数问题**：如选项字段非法，但明确不包括<mark style="background:#40a9ff">“首部校验和校验失败”，此时源头不可信，无需发送差错报文</mark>
	4. **改变路由/重定向**：路由器向源点通知路径更短的路由
	5. ~~源点抑制~~
2. **询问报文**：
	1. **回送请求与回答报文**：应用为 PING
	2. **时间戳请求与回答报文**

以下情形**不再发送 差错报文**：
1. <mark style="background:#fff88f">差错报文本身发生差错</mark>
2. <mark style="background:#fff88f">仅对第一个分片发送差错报文，后续分片不再发送</mark>
3. <mark style="background:#fff88f">多播或广播的数据报</mark>
4. <mark style="background:#fff88f">特殊地址的数据报</mark>

## IPv6
### IPv6 (报文)的特点
1. 支持即插即用：由于 IPv6 的空间地址极大，主机<mark style="background:#fff88f">可将其自己的 MAC 地址作为 IPv6 的接口标识符/主机号</mark>
2. <mark style="background:#fff88f">首部固定为 40 B</mark>
3. 取消**标识、标志、片偏移**字段，<mark style="background:#fff88f">不允许在中间路由器进行分片，若报文过大只能丢弃</mark>
4. <mark style="background:#fff88f">将 TTL 字段更名为 跳数限制 字段，作用不变</mark>
5. 取消 首部校验和，<mark style="background:#fff88f">不提供可靠传输，由传输层提供差错控制</mark>

### IPv6 地址
#### 缩写规则
1. 省略前导零
2. <mark style="background:#d3f8b6">双冒号替换连续全零组，即 "::"，但仅能使用一次</mark>

#### 地址分类
1. 未指明地址：全 0，不能用作目的地址
2. 环回地址：::1/128，作用与 IPv4 的环回地址一致
3. 多播地址：FF00::/8，作用与 IPv4 多播类似，可用作目的地址
4. 本地链路单播地址：仅用于本地链路内的通信
5. 全球单播地址
6. 任播：终点为一组计算机，但数据报仅交付给距离较近的计算机

### 从 IPv4 向 IPv6 的过渡
1. <mark style="background:#fff88f">双协议栈</mark>：主机上同时安装 IPv4 和 IPv6 协议栈，分别配置 IPv4 和 IPv6 地址
2. <mark style="background:#fff88f">隧道技术</mark>：将整个 IPv6 报文作为 IPv4 的数据字段，在 IPv4 的网络环境中传输

## 移动 IP
### 基本概念
1. **归属网络**：每个主机默认连接的网络或初始申请接入的网络
2. **永久地址（归属地址）**：在归属网络中的 IP 地址在其整个移动通信过程中是始终不变的
3. **归属代理**
  - 归属网络中，代表移动主机执行移动管理功能的实体
  - 归属代理通常就是连接在归属网络上的路由器
3. **外地网络（被访网络）**：移动主机当前漫游所在的网络
4. **外地代理**：外地网络中，帮助移动主机执行移动管理功能的实体
5. **转交地址**
  - 外地代理会为移动主机提供一个临时使用的属于外地网络的转交地址
  - 外地代理通常就是连接在外地网络上的路由器

## 路由算法与路由协议
### 路由算法
1. **静态路由与动态路由**
	1. 静态路由：由网络管理员手动配置
		1. 特点：实现简单，开销小，但不能及时适应网络状态的变化，适用于简单的小型网络
	2. 动态路由：更具网络状态的变化来动态调整自身的路由表
		1. 特点：能较好的适应网络状态变化，但实现复杂，开销也大，适用于复杂的大型网络
2. **距离-路径算法**：<mark style="background:#fff88f">仅要求每个结点知道：与相邻结点之间的距离；各邻居到达目的结点的最短距离</mark>。每个结点以自身为源点，独立运行 Bellman-Ford 算法。仅需与邻居结点交换整个路由表即可。
3. **链路状态算法**：<mark style="background:#fff88f">要求每个结点都掌握完整的全网拓扑结构</mark>，每个结点需要：<mark style="background:#d3f8b6">主动探查所有的相邻结点的状态</mark>；<mark style="background:#d3f8b6">定期检查自身的链路信息，通过洪泛法传播给全网所有节点</mark>

### 分层次的路由选择协议
整个互联网被划分为众多较小的 自治系统
1. 内部网关协议(IGP)：用于自治系统内部的路由选择，与其他自治系统所采用的协议无关，如 RIP，OSPF
2. 外部网关协议(EGP)：用于自治系统间的路由选择，如 BGP-4

每个自治系统都至少由一个或多个边界路由器，该些路由器不仅需要运行本系统的内部网关协议，还需要运行外部网关协议

### RIP
协议层次：<mark style="background:#fff88f">应用层</mark>协议，使用 <mark style="background:#fff88f">UDP</mark> 传送数据，端口为 <mark style="background:#fff88f">520</mark>
路由算法：<mark style="background:#fff88f">距离-向量算法</mark>

1. RIP 的规定
	1. <mark style="background:#fff88f">衡量网路距离的远近为：跳数</mark>，即规定直连网络的跳数为 1，每经过一个路由器，跳数加 1
	2. <mark style="background:#fff88f">“好”的路由：跳数最少的路由</mark>
	3. 网络不可达：<mark style="background:#40a9ff">一条路径最多包含 15 个路由器，因此跳数为 16 表示网络不可达</mark>
	4. 路由表项：**<目的网络 N，距离 d，下一跳路由器地址 X>**
	5. 距离向量，即其到所有网络的距离记录
2. RIP 的特点：
	1. 交换信息的对象：<mark style="background:#d3f8b6">仅与直接相连的路由器交换信息</mark>
	2. 交换信息的内容：<mark style="background:#d3f8b6">本路由器当前的完整路由表</mark>
	3. 交换信息的时间：<mark style="background:#d3f8b6">按固定的时间间隔交换信息(默认 30s)</mark>
	4. 触发更新：为加快路由表的收敛速度，<mark style="background:#d3f8b6">当网络拓扑结构发生变化时，路由器也会及时向相邻路由通告最新路由信息</mark>
3. **RIP 的基本工作原理**：对于每个相邻路由器发来的 RIP 报文，执行以下步骤：
	1. 对来自地址为 X 的相邻路由器的 RIP 报文，<mark style="background:#fff88f">首先修改其中所有的表项：将所有的“下一跳”更改为 X，并将距离字段的值加 1</mark>
	2. 对于上述修改的表项进行如下处理：
		1. 若原路由表<mark style="background:#fff88f">没有目的网络，将该表项加入路由表</mark>
		2. 若原路由表<mark style="background:#fff88f">存在目的网络，并下一条为 X，则将更新为新的表项</mark>
		3. 若源路由表<mark style="background:#fff88f">存在目的网络，但下一条不为 X，则根据距离字段决定是否替换</mark>
		4. 上述条件均不满足，则什么也不做
	3. 若<mark style="background:#fff88f">连续 180s 未收到某相邻的路由器的更新报文，则将其标记为 不可达</mark>
4. RIP 的优缺点：
	1. 优点：实现简单、开销小、收敛过程快；<mark style="background:#40a9ff">“好消息传的快”</mark>
	2. 缺点：
		1. 限制了网络的规模，即最大有效距离为 15(但**在一定程度上同时也限制了 环路的产生**)
		2. 网络规模越大，通信开销越大
		3. <mark style="background:#40a9ff">“坏消息传播的慢”</mark>

### OSPF
协议层次：<mark style="background:#fff88f">网络层</mark>协议，使用 <mark style="background:#fff88f">IP 数据报</mark>进行数据传输，<mark style="background:#fff88f">协议字段为 89</mark>
路由算法：<mark style="background:#fff88f">链路状态算法</mark>

1. OSPF 的特点：
	1. 使用<mark style="background:#fff88f">洪泛法</mark>向本自治系统内所有所有路由器发送信息，相邻路由器接力转发，但 <mark style="background:#fff88f">不回流</mark>，<mark style="background:#fff88f">不转发重复数据报</mark>
	2. 转发的信息为 <mark style="background:#fff88f">本路由器与其相邻路由器之间的链路状态，即局部的拓扑信息</mark>，而非全局路由表
	3. <mark style="background:#40a9ff">仅在链路状态发生改变时才触发洪泛更新</mark>
2. OSPF 的其他优势：
	1. 支持对每条链路路由<mark style="background:#d3f8b6">设置不同的代价</mark>
	2. 存在多条到同一目的网络且代价相同的路径时，<mark style="background:#d3f8b6">可实现负载分担</mark>
	3. 具备兼备能力，<mark style="background:#d3f8b6">确保仅在可信的路由器之间交换链路信息</mark>
	4. 支持可变长子网掩码和无分类编址
	5. 每条链路通告均携带一个 32 bit 序列，序号越大，表示状态越新
3. OSPF 的区域划分
	1. <mark style="background:#fff88f">OSPF 支持将一个自治系统划分为若干更小的区域</mark>，好处是：将洪泛法交换链路状态信息的范围限制在各区域内，而非整个 AS 系统，从而<mark style="background:#fff88f">减少网络通信开销</mark>
	2. **区域边界路由器**：每个区域由一个或着多个区域边界路由器负责该为进出该区域的报文提供路由
	3. **主干区域**：必不可少的区域配置，<mark style="background:#fff88f">包含 AS 内所有区域边界路由器</mark>，用于连接其他区域
	4. 不同区域之间分组的转发路径：**源区域 -> 区域边界路由器 -> 主干区域 -> 目的区域的边界路由器 -> 目的地**
4. OSPF 的五种分组类型
	1. **问候**/ HELLO 分组：用于发现邻居并保持邻接关系，确认链路双向连通性
	2. **数据库描述分组**/ DD：向邻居发送自己的链路状态数据库中的所有链路状态项目的**摘要信息**
	3. **链路状态请求分组**/ LSR：向邻居请求发送某些链路状态项目的**详细信息**
	4. **链路状态更新分组**/ LUR：通过洪泛法向全网发送链路状态通告/LSA，是 OSPF **最核心的部分**
	5. **链路状态确认分组**/ LSAck，对链路更新分组的确认
5. OSPF 的工作原理
	1. 相邻路由器之间 每隔 10 s 周期性地交换问候分组，以确认和维护邻居的可达性。若在 40 s 内未接收到邻居的问候分组则判定邻居不可达，立即触发 链路状态数据库的更新，并重新生成 路由表。<mark style="background:#fff88f">网络中传送的大多数 OSPF 分组都是 问候分组</mark>
	2. 相邻路由器之间通过 数据库描述分组 交换各自 LSDB 中链路状态通告的摘要信息；随后路由器将其路由表与摘要信息进行对比，使用 链路状态请求分组 向邻居请求自身缺失或过期的 LSA 详细信息；对方则通过 链路状态更新分组 发送所请求的 LSA，**接收方成功接收后需返回 链路状态确认分组 以确保可靠传输**
	3. 一旦路由器检测到自己的链路状态变化，就会立即生成新的 LSA，并通过 链路状态更新分组 以可靠洪泛方式向整个区域传播；其他路由器收到后，同样必须返回确认

>[!caution] OSPF 的路由表
>虽然路由器可以得到完整的路径，但路由表中仅会存储“下一跳”，而不是完整路径，因为 只有到了下一跳才能确定再下一跳怎么走

### BGP
协议层次：<mark style="background:#fff88f">应用层</mark>协议，通过 <mark style="background:#fff88f">TCP</mark> 进行通信；<mark style="background:#fff88f">外部网关协议</mark>
路由算法：<mark style="background:#fff88f">路径向量算法</mark>

1. BGP 提供比较好的路由，而非最佳路由
	1. 互联网规模庞大，使得 AS 之间的路由选择非常困难
	2. AS 之间路由选择必须考虑 政治、安全或经济等有关因素
2. BGP 路由格式：**<前缀，BGP 属性> = <前缀，AS-PSTH，NEXT-HOP>**
	1. AS-PATH：记录了该 BGP 路由经过的自治系统序列
	2. NEXT-HOP：表示接收该 BGP 路由的路由器去往目的网络时应使用的下一跳地址
3. BGP 会话
	1. eBGP 会话：跨越两个 AS 的 BGP 会话(存在直接的物理链路)
	2. iBGP 会话：位于同一个 AS 内的 BGP 会话；<mark style="background:#fff88f">BGP 要求在 AS 内的任意两个路由器之间都要建立 iBGP 会话</mark>(<mark style="background:#fff88f">全连通，即使没有直接物理链路连接</mark>) \[其实仅有少部分内部路由器需要运行 BGP 协议\]
	3. BGP 学习：
		1. <mark style="background:#fff88f">eBGP 路由器会将学习到的路由传递给 iBGP 路由器，而 iBGP 路由器不能将学习到的路由传递给 eBGP</mark>
		2. eBGP 路由器将学习到的 BGP 路由直接传递给 iBGP 路由器，并由 iBGP 路由器独立运行路由算法将“下一跳”信息修正为 到达该 eBGP 路由器的下一跳
		3. eBGP 路由器会将 BGP 路由中的“下一跳”修改为自己，然后才传递给 eBGP 路由器
4. BGP 路由选择
	1. 首先选择 <mark style="background:#d3f8b6">本地偏好值高的路由</mark>
		1. 可由管理员根据政治、经济上的策略来设置；可预见即使高速链路过载，BGP 也无法自动实现均衡负载
	2. 其次选择 <mark style="background:#d3f8b6">AS 跳数最少/AS-PATH 最短的路由</mark>
	3. 再其次选择 <mark style="background:#d3f8b6">热土豆路由选择算法</mark>
		1. 基本思想为 **“尽快脱手”**，使得分组经过最少的转发次数离开本 AS，此时要使用的 内部网关协议
	4. 最后选择 <mark style="background:#d3f8b6">BGP 标识符最小的路由</mark>
		1. BGP 报文首部有 BGP 标识符 字段，是运行 BGP 路由器的唯一标识符
5. BGP 的四种报文
	1. 打开报文/Open，用于与 BGP 会话对等方建立关系，使得通信初始化
	2. 更新报文/Update，用于通告某一路由的信息，以及列出要撤销的多条路由
	3. 保活报文/Keepalive，用于周期性地证实与对等方的连通性
	4. 通知报文/Notification，用于发送检测到的差错，并立即关闭 BGP 会话



### 数据转发
1. 其他主机向处于外地网络的移动设备发送信息：该主机发送的数据报中 目的 IP 地址 填写该移动设备的永久 IP 地址，即该数据报转发至该设备的归属网络，并由该设备的归属代理转发至外地代理，再由外地代理直接交付给该设备
2. 处于外地网络的移动设备向其他主机发送信息：数据报的目的 IP 地址 填写该设备的永久 IP 地址，直接通过外地网络的外地代理转发，无需通过归属代理 


## 网络层设备
### 冲突域与广播域
1. 冲突域：是指<mark style="background:#fff88f">连接到同一物理介质</mark>上的所有结点的集合，该些结点之间<mark style="background:#fff88f">存在介质争用的现象</mark>；属于 <mark style="background:#fff88f">物理层</mark>的概念
2. 广播域：是指<mark style="background:#fff88f">能够接收同一广播帧</mark>的所有集合，属于 <mark style="background:#fff88f">数据链路层</mark>的概念

设备与冲突域和广播域：
1. <mark style="background:#40a9ff">集线器、中继器</mark><mark style="background:#fff88f">无法分离冲突域</mark>，其所有端口属于同一个冲突域；<mark style="background:#40a9ff">网桥、交换机、路由器</mark>均<mark style="background:#fff88f">可划分冲突域</mark>
2. <mark style="background:#40a9ff">集线器、中继器、网桥、交换机</mark> 所连接的结点都<mark style="background:#fff88f">属于同一个广播域</mark>；<mark style="background:#40a9ff">路由器</mark>用于连接不同的局域网，<mark style="background:#fff88f">可以划分广播域</mark>

### 路由器的组成和功能
1. 路由选择/控制平面
	1. 选择处理机：根据路由选择协议构建路由表，并周期性地与相邻路由器交换路由信息，以更新和维护路由表
	2. 路由选择协议
	3. 路由表：基于路由选择算法得到的，用于路由选择，表项通常为：<目的网络 IP 地址，子网掩码，下一跳 IP 地址，接口>，并包含一条指向互联网的默认路由；通常由软件实现
2. 分组转发/数据平面
	1. 交换结构
		1. 连接输入/出端口的高速链路
		2. 转发表：由路由表得出，其表项与路由表有直接的对应关系；同样可配置一条默认路由，并且既可以使用软件实现，又可以使用硬件实现
	2. 输入/出端口，在端口处均设有 缓冲区，用于暂存待处理或待转发的分组，并可以进行差错检测

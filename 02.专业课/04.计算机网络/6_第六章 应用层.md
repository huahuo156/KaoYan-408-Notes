# 第六章 应用层
## 网络应用模型
### 客户/服务器模型
1. 存在始终一个处于开启状态的主机，即服务器
2. 客户主动发起服务请求，并预先知道服务器程序的地址；而服务器不必预先知道
3. 服务器与客户地位不对等，客户由服务器集中管理
4. 客户之间不能直接通信
5. 可扩展性不佳

### P2P 模型
1. 每个结点都处于对等地位
2. 多个结点之间可以直接通信
3. 可扩展性好
4. 减轻了中心服务器的计算和带宽压力
5. 结点在获取服务的同时，还需为其他结点提供服务
6. 可能会造成网络严重拥塞

## 域名系统/DNS

DNS 采用客户/服务器模式，运行在 UDP 之上，使用 53 端口

### 层次域名空间
采用树状命名方法，形成 顶级域、二级域、三级域等层次结构；每个域名由一系列标号组成，各标号之间用 ‘.’ 分隔
标号的要求：
1. 标号中的英文字母不区分大小写
2. 标号中除 ‘-’ 外，不得使用其他标点符号
3. 每个标号不超过 63 个字符，整个域名(包括分隔点)的总长度不超过 255 个字符
4. 级别最低的域名写在最左边，级别最高的顶级域名写在最右边

### 域名服务器
每个域名服务器不仅要能解析部分域名到 IP 地址，还要维护指向其他域名服务器的信息；当自身无法完成解析时，要能知道向哪个服务器进一步查询

1. 根域名服务器：是 DNS 层次结构中的最高级别。所有根域名服务器都知道全部顶级域名服务器的域名和 IP 地址。每个根域名服务器对应的是由多个冗余服务器组成的集群
2. 顶级域名服务器：负责管理在其下注册的所有二级域名
3. 权限域名服务器：负责管理特定区的域名信息；该服务器器总是能将其管辖的主机名解析为对应的 IP 地址
4. 本地域名服务器：当主机发起 DNS 查询请求时，该请求首先被发送给其配置的本地域名服务器；保存着 DNS 缓存，并设置着 生存日期

### 域名解析过程
1. 递归查询：“虽然我不知道答案，但是我尽力帮你找到答案”
2. 迭代查询：“虽然我不知道答案，但是我知道你下一步应该向谁查询”

主机向 本地域名服务器 总是采取 递归查询；本地域名服务器向其他域名服务器可采用 递归查询(实际中几乎不使用) 或 迭代查询，并且总是从 根服务器 开始

## 文件传输协议
### FTP 的特点
FTP 提供的功能：
1. 支持在异构网络中的任意两台主机之间可靠传输文件
2. 支持不同类型主机系统之间的文件传输
3. 通过用户权限管理，提供对远程 FTP 服务器上文件的管理能力
4. 通过匿名 FTP 方式，实现公共文件的共享

FTP 的特点：
1. 采用客户/服务器模式，基于 TCP 提供可靠传输
2. FTP 是有状态协议，服务器需在整个会话期间维护用户的状态信息
3. 服务器进程由两部分组成：
	1. 主进程，一个，负责接收新的请求
	2. 从属进程，若干，处理单个客户的请求
4. 建立两个并行的 TCP 链接：控制连接、数据连接

### 控制连接与数据连接
1. 控制连接：服务器监听 21 号端口，等待客户端连接。控制连接本身不传递文件数据，并在整个会话过程中保持打开状态
2. 数据连接：完成文件内容的传输，每次传输前建立连接，并在传输结束后立即关闭
	1. 主动模式/POST(默认)：即服务器主动连接客户端；客户端通过 控制连接 发送下载或上传请求，以及此次 传输数据所需的随机本地端口号；随后服务器主动通过 20 号端口连接客户端
	2. 被动模式/PASV：即客户端主动连接服务器；客户端通过 控制连接 发送下载或上传请求，服务器响应并发送此次数据传输所需的随机本地端口号；随后客户端采用本地随机端口号与服务器进行连接。由于 NAT 的存在，实际情况采用的是 被动模式。

注意：客户端请求服务器返回文件列表命令是通过 控制连接 发送给服务器的，而服务器返回的 传输文件列表信息 是通过 数据连接 发送给客户端的

## 电子邮件
### 电子邮件系统
组成：
1. 用户代理
2. 邮件服务器：采用客户/服务器模式
3. 邮件传输协议：
	1. SMTP：用于发送邮件，用户代理->邮件服务器，邮件服务器->邮件服务器
	2. POP3/IMAP：用于从邮件服务器获取邮件，邮件服务器->用户代理

### 电子邮件格式与 MIME
1. 电子邮件格式：
	1. 信封：由邮件系统自动根据首部信息生成
	2. 内容：
		1. 首部：
			1. From：来自谁，必填关键字，但一般由邮件系统自动填充
			2. To：发送给谁，必填关键字
			3. Subject：主体，可选
		2. 主体：-

2. MIME
	1. SMTP 仅支持传输 7 bit ASCII 文本邮件
	2. MIME 并未修改 SMTP，而是在其基础上进行扩展。当需发送非 ASCII 文件时，需用 MIME 将非 ASCII 数据编码为 ASCII 格式，再交给 SMTP 传输

### SMTP 与 POP3
1. SMTP
	1. 采用客户/服务器模式，基于 TCP 连接，使用 52 号端口
	2. 邮件服务器之间直接采用 TCP 连接，无论两者之间距离有多远，相距路由器有多少
	3. 正式发送正文前会发送多个 RCPT 命令，避免发送给错误的邮件服务器
2. POP3
	1. 采用客户/服务器模式，基于 TCP 连接，使用 110 端口
	2. 支持：下载并保存；下载并删除


## 万维网
### 万维网的组成
1. 统一资源定界符/URL
2. 超文本传输协议/HTTP，基于 TCP 连接的可靠传输
3. 超文本标记语言/HTML

### HTTP
1. HTTP 特点
	1. 无连接
	2. 无状态
		1. 可采用 Cooike 与数据库来实现用户行为追踪：当用户首次访问某个启用 Cooike 的网站时，服务器会为其生成一个唯一巍峨 Cooike 标识码，并以此在数据库中创建一个索引记录，并在 Http 响应报文中添加 Set-Cooike 首部行；此后浏览器再次访问该网站时会附加 Cooike 首部行
	3. HTTP 1.0 仅支持非持续连接，HTTP 1.1 默认采用持续连接
		1. 非持续连接情况下，每个网页元素的请求都必须串行建立一个新的 TCP 连接，但现浏览器通常支持 多个并行 TCP 连接
		2. 持续连接情况下，客户可继续使用同一连接继续发送后续的 HTTP 请求并接收响应
		3. 非流水线工作方式：客户端必须等待前一个响应达到后才能发送下一个请求
		4. 流水新工作方式：客户端可持续发送多个对象的请求，服务器也可以连续发送响应
2. HTTP 请求报文中常用的几个方法：
	1. GET：请求读取由 URL 标识的信息
	2. HEAD：请求读取由 URL 标识的信息的首部
	3. POST：给服务器添加信息
